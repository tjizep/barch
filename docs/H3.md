## H3 geospatial index

There is no geo command. Put points in a keyspace of their own
(`spatial_data`) so they stay out of the document space.

Each point is one composite key: the Uber H3 cell as a decimal
integer, a space, then a unique id (a name, or a counter). `SET`
splits on that space. The cell token is a number, so the parser
encodes it as an integer — the same (base 128)+1 order every numeric
key already uses. Nearby cells then sit nearby in the trie.

```redis
spatial_data:SET "599686042433355775 place" {"lat":37.8,"long":-122.4,"name":"place"}
```

`599686042433355775` is `int(h3.latlng_to_cell(lat, lng, 12), 16)`.
The examples use resolution 12 for the stored cell.

#### Time Complexity O(k) to write one point, O(k + m) to RANGE a cell

A miss RANGE answers an empty array. A SET of the same cell and id
overwrites the value.

#### Arguments

- key (composite string) -- `<h3> <id>`. The first token is the cell
  as a decimal integer. The second is any unique id that is not
  itself a number you need to sort as text.
- value -- the point payload. `geo.py` stores the point as text;
  `overture.py` stores the address JSON.

### Example

A search does not RANGE the whole world. Convert the query to a
resolution-12 cell, take its resolution-8 parent, then RANGE from
that parent's first child to its last child — that span is
contiguous in H3's child order, so it is one numeric range:

```redis
spatial_data:RANGE "<first_child> 0" "<last_child> 99999999999999" 10
```

`geo.py` builds those two integers with `h3.child_pos_to_cell`.
`overture.py` writes the same key shape at import
(`{h3_index} {counter}`). Both live under `examples/flask/`.

Keep the space ordered (`spatial_data.ordered`). `REM` the composite
key when the point is deleted.
